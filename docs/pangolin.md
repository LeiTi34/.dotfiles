# Pangolin client

The `pangolin-client` feature (in `profile-development`) connects the host
to the private resources on `https://pangolin.leidwein.com` as a user device:
the systemd unit `pangolin-client` runs `pangolin up client --attach` as root
at boot with `SUDO_USER=alex`, so it uses alex's login in
`~/.config/pangolin/accounts.json`, like `sudo pangolin up` does. Resource
access follows the Pangolin user and its roles.

## Login

Once per host:

```sh
pangolin login https://pangolin.leidwein.com
sudo systemctl start pangolin-client
```

`pangolin login` opens the Pangolin login page in the browser (OIDC or
password), asks for the organization and registers the device. The unit is
skipped (`ConditionPathExists`) until `accounts.json` exists; after that it
starts at every boot. Logs: `journalctl -u pangolin-client`.

The login is a Pangolin session that expires after
`dashboard_session_length_hours` (server default 30 days) and is extended
while the client uses it. After a longer break, or after `pangolin logout`,
the unit fails; log in again and restart it.

Don't use `pangolin up`/`pangolin down` while the unit runs (only one client
can run); stop or start the unit instead.

## DNS

The client overrides DNS by default (aliases of private resources resolve
through its DNS proxy). On these hosts `/etc/resolv.conf` is generated by
resolvconf, so it registers the proxy with `resolvconf -a pangolin`; that's
why the unit has resolvconf in its `PATH`. `sudo pangolin reset-dns` removes a
leftover override after a crash.
